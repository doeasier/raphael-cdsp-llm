  ggml_backend_sched_backend_from_buffer() at L1296-1316 returns the FIRST
  backend for which (supports_buft(buffer->buft) && supports_op(op)).
  Our cDSP backend is backend[0] and supports_buft() accepts all host buffers,
  so a MUL_MAT is assigned to cDSP here; RMS_NORM / SILU / SOFT_MAX / ADD
  (supports_op == false) fall through to the CPU backend, which is the LAST
  backend. Pass 2 only fills nodes still == -1, so this assignment is final.

  Our device reports caps.async=false / events=false / mmap_support=false
  (ggml-cdsp.cpp:850-856) and synchronize() is a no-op because
  cdsp_graph_compute() is fully synchronous (L702, L704-801). Every split is
  therefore a serial CPU -> FastRPC round trip -> CPU handoff.

  cdsp_graph_compute() L792-800 currently SKIPS every non-MUL_MAT node:
        // any other op type is handled by the CPU backend (scheduler does not
        // assign it to us because supports_op() returns false for it)
  If supports_op() were widened without implementing those ops, the DSP would
  silently leave their dst tensors unwritten -> silent numerical corruption.
